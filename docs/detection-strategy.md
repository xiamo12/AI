# AI 文本检测策略与运行方式

## 项目运行方式

### 纯前端运行（默认模式）

本项目**可以在纯前端环境下独立运行**，不依赖任何后端服务。

- 全部检测逻辑实现在 `utils/` 目录下，使用纯 JavaScript
- 在微信小程序的服务线程中同步执行，单次检测耗时约 35-82ms
- 无网络请求，完全离线可用

### 后端增强模式（可选）

项目附带一个 Python SVM 检测服务，可提供额外的机器学习评分进行融合加权：

- **后端代码地址**：`../ai_text_detector/`（与 `miniprogram/` 同级）
- **技术栈**：Python Flask + SVM 集成分类器
- **接口**：`POST /detect`，接收 `{ text }`，返回 `{ aiScore, verdict, perModelVotes, elapsed }`
- **启用方式**：在 `pages/index/index.js` 中将 `svmServer` 指向实际服务地址（默认 `http://localhost:3100`）
- **超时策略**：3 秒无响应则自动降级为纯本地结果
- **融合权重**：本地检测 40% + SVM 检测 60%
- **部署方式**：`ai_text_detector/` 目录包含 `Dockerfile`，可容器化部署

> **注意**：后端 Python 服务不随小程序代码提交到 Git 仓库（已在 `.gitignore` 中忽略 `ai-detector/` 目录，且后端独立于 `miniprogram/` 路径下）。

## 检测策略（v3.0）

检测系统采用 **4 层管线架构 + 多检测器融合**，从模式匹配、统计特征、语义分析和段落一致性四个维度综合评分。

### 层一：模式匹配指纹库（`aiTextDetection.js`）

基于正则表达式的 AI 句式识别，覆盖以下类别：

| 类别 | 示例 | 权重 |
|---|---|---|
| 对照结构 | 不是…而是…、不是…只是… | 8 |
| 三重否定 | 不是A不是B而是C | 9 |
| 结构模板 | 首先…其次…最后… | 7 |
| 让步结构 | 虽然…但不可否认… | 6 |
| 价值升华 | 真正的成长/价值/意义 | 6 |
| 框架前置 | 从…的角度来看、基于此 | 5 |
| 总结套话 | 综上所述、显而易见、归根结底 | 4 |
| 概念词 | 底层逻辑、颗粒度、赋能 | 1-4 |
| 公文套话 | 以…为核心、以…为导向 | 5 |
| 鸡汤升华 | 未来可期、愿你… | 4 |
| 学术套话 | 相关研究表明、文献综述表明 | 5 |
| 营销话术 | 月入过万、看完你就懂了 | 5-6 |
| 小红书模板 | 谁懂啊、绝绝子、建议所有…都去… | 3-5 |

共约 **40+ 句式模式 + 70+ 模板短语 + 90+ 四字短语**（四字短语主要针对公文风格 AI 文本）。

### 层二：统计特征引擎（`aiDetector.js`）— 纯 JS 移植版

这是 Python 版本的 JavaScript 移植，包含以下特征计算：

1. **字符级 n-gram 特征**：字符 trigram/quadgram 的 TTR 和熵值
2. **句法多样性**：句首 2 字多样性、句长标准差
3. **突发系数（Burstiness）**：基于句长方差的节奏一致性
4. **Zipfian 偏离度**：词频分布与幂律分布的偏离程度
5. **标点分布**：各类标点的使用频率分布熵
6. **虚词密度**：50+ 个中文虚词（的了着过把被…）占比
7. **段落均匀度**：滑动窗口中字符 bigram 熵的变化幅度
8. **句子相似度**：所有句子对的余弦相似度矩阵（上限 80 句防 O(n²) 溢出）

### 层三：语义分析（`aiSemanticDetector.js`）— 无外部依赖

完全自包含的语义分析，不需要预训练模型或外部语料库：

1. **困惑度计算**：基于自建 4-gram 字符语言模型，统计条件概率
2. **过渡平滑度**：相邻句子的 Jaccard 关键词重叠度，判断是否过于连贯
3. **词汇多样性曲线**：前半段与后半段的字符 TTR 差值，检测词汇变化是否均匀

语义得分以 **30% 权重** 融合到总分。

### 层四：段落一致性检测（`aiSemanticConsistency.js`）

分析段落级别的逻辑连贯性：

1. **语义断层检测**：相邻段落的 2-4 字 topic n-gram Jaccard 相似度，阈值 < 0.002 标记断层
2. **观点矛盾检测**：20+ 组反义词对的正则匹配（应该/不应该、支持/反对、提倡/摒弃等）
3. **论据重复检测**：证据关键词的跨段落重叠（研究显示、数据表明、实验证明等）

一致性得分 > 30 时，总分加 0-6 分。

### 评分融合公式

```
score = baseline(4-10)
      + 句式命中 × patternMul(1.5-2.3, capped 45)
      + 句长特征(0-7)
      + 方差惩罚(0-5)
      + 低去重率惩罚(0-4)
      + 四字短语(0-8)
      + 虚词密度(0-4)
      + n-gram 复现率(0-11)
      - 人类信号扣分(0-15)
      - 具体事实扣分(0-18)
      - 交叉信号缓扣(0-5)
      = rawScore

score = rawScore × 0.70 + 语义分析分 × 0.30    ← 语义融合
score += 一致性扣分 (0-6)                        ← 段落一致性
score = rawScore × 0.80 + 本地检测器 × 0.20     ← 统计特征融合
```

最终分数范围 **3-96**，映射为风险等级。

### 风险等级

| 分数 | 等级 |
|---|---|
| ≥ 85 | AI痕迹极高频 |
| 70-84 | AI痕迹高频 |
| 50-69 | AI痕迹严重 |
| 30-49 | AI痕迹一般 |
| 10-29 | AI痕迹较低 |
| < 10 | AI痕迹极低 |

### 体裁感知

系统会根据场景（通用文本/论文/公众号/小红书）自动调整：
- **论文/作业**：更关注学术套话和结构模板，patternMul=1.5
- **公众号**：权重倾向于营销口吻和鸡汤升华，patternMul=2.3
- **小红书**：包含独特的小红书句式库（谁懂啊/闭眼入等），patternMul=1.8

此外，系统会通过 `detectGenre()` 自动识别议论文/叙事文，并微调评分。

### 上下文感知（v3.0 新增）

为了避免误判，系统对特定模式进行上下文分析：

1. **"不是…而是"类句式**：检查"而是"后的 15 字是否有具体人称/引号/具体名词 → 人类写作特征则降权至 20%
2. **概念词使用场景**：检查"底层逻辑""颗粒度"等概念词是否出现在问句中或引号内 → 自然使用则不计入 AI 分数
3. **人类信号分级**：强人声（我记得/我见过）权重 ×3，普通人声（比如/有一次）权重 ×0.5

## 运行时执行流程

```
用户点击"检测"
  │
  ├─ index.js detectText()
  │    ├─ analyzeArticle(text, { articleType })  ← 同步，35-82ms
  │    ├─ 异步请求 SVM 后端 (3s 超时回退)
  │    └─ wx.setStorageSync → wx.navigateTo 结果页
  │
  ├─ analyzeArticle() 内部管线（见上文 4 层架构）
  │    └─ 返回 ~30 字段结果对象
  │
  └─ result.js onShow()
       ├─ wx.getStorageSync 读取结果
       ├─ 计算 UI 状态 (riskLabel, indicatorLeft)
       └─ setData 渲染页面
```

所有检测计算在 **微信服务线程同步执行**。单次完整管线（4 层全部运行）在 2000-16000 字文本上实测 35-82ms。

## 模块依赖关系

```
pages/index/index.js
  └→ utils/aiTextEngine.js (兼容层)
       ├→ utils/aiTextDetection.js     (主管线编排 + 模式匹配)
       │    ├→ utils/aiDetector.js     (统计特征引擎，纯 JS 移植)
       │    ├→ utils/aiSemanticDetector.js   (语义分析，4-gram 语言模型)
       │    ├→ utils/aiSemanticConsistency.js (段落一致性检测)
       │    └→ utils/util.js           (工具函数：normalizeText, splitSentences)
       ├→ utils/aiTextHistory.js       (历史记录管理)
       └→ utils/util.js

后端增强（可选）：
pages/index/index.js
  └→ wx.request → http://localhost:3100/detect
       └→ ai_text_detector/flask_server.py
            ├→ statistical_features.py
            ├→ deep_learning_features.py
            └→ ensemble_classifier.py
```
