## 3. 状态流转

### 3.1 检测流程

```
IDLE → INPUTTING → ANALYZING → RESULT → [VIEW_ISSUES | GO_OPTIMIZE]
                    ↑                             │
                    └──────── BACK ────────────────┘
```

### 3.2 改写流程

```
IDLE → INPUTTING → SETTINGS → REWRITING → RESULT
                    ↑                        │
                    └────── BACK ────────────┘
```

### 3.3 错误状态

```
[错误] → Toast 提示 → IDLE
[空输入] → Toast "请先输入文章" → IDLE
[API失败] → Toast "DeepSeek请求失败" → 回退本地
[无变化] → 自动执行 ensureChanged 策略 → 仍无变化则返回原文
```

## 4. 关键交互细节

### 4.1 首页

- 切换 Tab「AI检测/去痕改写」：
  - 保留已输入的文本
  - 切换后按钮文本变化（「AI检测」→「去痕改写」）
- 粘贴按钮：读取剪贴板填入
- 示例按钮：填入预设 AI 味文本用于演示
- 清空按钮：重置输入

### 4.2 检测结果

- 评分环形展示（SVG 或 canvas）
- 段落列表按风险排序（高→低）
- 点击段落定位到对应文本范围
- 来源分析展示 Top 5 AI 味特征

### 4.3 问题句子

- 按风险等级排列（高→低）
- 每条展示：句子原文、问题标签、改写建议、示例改写
- 可展开/收起更多信息

### 4.4 优化结果

- 左右分栏 / 上下对照 diff 视图
- 变更部分高亮标注（新增绿色、删除红色）
- 质量评估卡片（AI率变化、通顺度、风格匹配度）
- 复制改写结果、分享

## 5. 导航映射

| 来源 | 动作 | 目标 | 数据传递 |
|------|------|------|----------|
| 首页 | 点击「AI检测」 | 检测结果 | STORAGE_KEYS.currentAnalysis |
| 首页 | 点击「去痕改写」 | 优化设置 | 原文文本 |
| 检测结果 | 点击「查看问题句子」 | 问题句子 | STORAGE_KEYS.currentAnalysis |
| 检测结果 | 点击「去改写」 | 优化设置 | STORAGE_KEYS.currentAnalysis |
| 问题句子 | 返回 | 检测结果 | 直接 navigateBack |
| 优化设置 | 点击「开始优化」 | 优化结果 | STORAGE_KEYS.currentOptimize |
| 优化结果 | 返回 | 首页 | navigateBack |

## 6. 用户场景

### 场景 A：学生检测论文

1. 打开小程序 → 首页「AI检测」
2. 粘贴论文段落 / 选择「论文/作业」
3. 点击「AI检测」
4. 查看评分：78% → 高风险
5. 查看问题句子 → 发现 3 个「不是…而是…」句式
6. 点击「去改写」→ 选择强度「深度」→ 优化
7. 对比改前改后 → 复制改写结果

### 场景 B：公众号作者日常写作

1. 打开小程序 → 首页「去痕改写」
2. 粘贴草稿 / 选择「公众号文章」
3. 点击「去痕改写」
4. 查看评估（86% → 32%）
5. 查看 diff 确认改动合理
6. 复制回公众号编辑器发布
